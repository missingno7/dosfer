DOSfer legacy RGB3 V40-L validation
===================================

Scope
-----
- fixed standard QR Version 40-L (177x177 modules)
- legacy 16-bit Open Watcom sender
- planar EGA/VGA Mode 0Dh RGB3 output plus /BW compatibility
- default /WINDOW:66 and /RE:3
- Android receiver channel split is validated separately by the JVM tests
  summarized below

Host checks performed for this revision
---------------------------------------

1. Source/API syntax
   - sender/config/producer/protocol/VGA/timing/qrcodegen sources were checked
     together with GCC and lightweight DOS compatibility stubs.
   - release, DOSFER_DEVTOOLS and DOSFER_PROFILE code paths were included.
   - Host-only warnings remain expected where Watcom's 32-bit `unsigned long`,
     `#pragma aux`, segmented pointers and signed wraparound differ from the
     64-bit host compiler model.

2. Fixed V40-L encoder and raster oracle
   - the two portable host oracles also complete cleanly under
     AddressSanitizer and UndefinedBehaviorSanitizer
   - every mask 0..7
   - 250 deterministic random transitions per mask
   - frame lengths 0..2952 bytes
   - optimized pack + block ECC + sequential emitter compared byte-for-byte
     with canonical V40-L codewords
   - packed raster delta compared with a canonical full matrix redraw
   - result: PASS

3. Encoded XOR3 parity derivation
   - every mask 0..7
   - random equal-length source frames
   - source codewords XORed, then corrected by the desired 48-byte DOSfer
     header and its degree-30 first-block Reed-Solomon correction
   - all 3706 derived codewords compared with canonical parity encoding
   - result: PASS

4. RGB3 protocol parity
   - fixed C/Java-compatible XOR3 whitening vector
   - lengths 0, 1, 3, 4, 47, 128, 1024 and 2904 bytes
   - equal-length parity wire payload compared with the XOR of the three DATA
     wire payloads
   - derived V40-L parity compared with canonical encoding for every mask
   - result: PASS

5. Repository protocol regression
   - deterministic JSON vectors: 2 files verified
   - Python protocol suite: 16 tests
   - result: PASS

6. Android-independent JVM regression
   - 42 unit tests compiled directly with Java 21 (`--release 17`) and
     lightweight temporary Android/JUnit stubs
   - camera geometry and mode selection
   - protocol parsing, whitening and stride-3 recovery
   - RGB3 channel de-duplication and BW/RGB3 mode detection
   - BT.601 YUV-to-R/G/B conversion, including strides and buffer positions
   - result: PASS

7. Camera scanner API smoke compile
   - the production CameraScanner, RGB3 channel wrappers and supporting camera
     classes compiled with Java 17 language rules against lightweight Camera2,
     CameraX and ZXing-C++ API stubs
   - result: PASS

Not target-built or optically validated here
--------------------------------------------
- Open Watcom was not available, so DOSFER.EXE was not produced.
- The Android Gradle wrapper could not download Gradle 8.11.1 because
  services.gradle.org was unreachable, so no APK/full Gradle build was
  produced. The Android-independent production classes and 42 tests were
  compiled and run with a local javac harness instead.
- No real EGA/VGA adapter, CRT, DOSBox/86Box timing run or phone camera was
  available in this environment.
- The planar register path therefore still needs a target build, hardware
  readback and end-to-end optical throughput measurement.

Run the two portable C oracles with the commands in tests/README.md. Build the
real executable with build.bat in an Open Watcom environment, then validate
/BENCH, /RGB3 and /BW on the intended hardware.
